# 03 · 骰点、Roll、Formula

## 设计原则

**抽样与引用分离**：每次骰点表达式求值发生一次随机抽样；保存结果之后，读变量、数组元素、属性或者把结果参与计算，都不会重新抽样。只有重新求值骰点表达式、调用新的骰点函数或显式 `.eval()` 才会抽样。

## 普通骰点表达式

| 语法 | 含义 |
|---|---|
| `d20` | 1 枚 20 面骰 |
| `3d6` | 3 枚 6 面骰，默认加和 |
| `(等级 + 1)d(20)` | 运行时计算骰数、面数 |
| `2d20kh1` / `2d20k1` | 保留最高 1 枚 |
| `2d20kl1` / `2d20q1` | 保留最低 1 枚 |
| `4d6dl1`, `4d6dh1` | 丢弃最低 / 最高 |
| `3d20min10`, `3d20max15` | 每枚骰下限 / 上限 |
| `d20优势` / `d20劣势` | `2d20kh1` / `2d20kl1` |

修饰符只能用于骰点结果的骰子集合，且一个骰点字面量中的修饰序列必须符合唯一顺序：`min`/`max`（每骰截断）→ `kh`/`kl`/`dh`/`dl`（筛选）→ 汇总；同一类筛选修饰符不能组合两次。`1d6kh2` 等不合理的数量在静态可知时提前诊断。`0d6`、`d0` 无效。`d20优势` 与其他取高取低修饰不可连用，避免多重解释。

语法解析有意限制：不把 `a2`、`b2`、`f`、`4c3m7` 之类有潜在变量冲突的规则直接注入普通标识符词法空间。

## 规则骰空间

`r"..."` 在独立的规则骰子文法中解析并**立即求值**。其结果为 Roll：

```text
普通 := 2d6 + 3
奖励 := r"b2"       # CoC 奖励骰
惩罚 := r"p1"       # CoC 惩罚骰
命运 := r"f"        # Fate
成功数 := r"5a9k2"  # WoD，成功数规则
爆骰 := r"4c3m7"    # Double Cross
```

`roll("b2")` 则用于通过字符串动态选择/构造规则骰。`roll` 接受 **String** 而非 Roll；`roll(d20)` 应报告类型错误，防止“是否又掷一次”的混淆。

标准宿主按规则提供：

```text
coc.bonus(2)                    # 等价于 r"b2"
coc.penalty(1)                  # 等价于 r"p1"
fate.roll()                     # 等价于 r"f"
wod.roll(5, again: 9, target: 2) # 对应 5a9k2 的语义
# Double Cross 标准函数的具名参数定义见未决问题（避免误确定历史语法参数）
```

CoC/Fate/WoD/DX 的解析、结果语义须与所选规则配置一致。由于各骰系内部修饰符不是通用主语言语法，v0.1 **保留功能入口但不保证所有旧规则源码无需转换**。自定义规则仅在 `r"..."` 或 `roll(string)` 的独立文法中注册；自定义规则不得修改普通标识符解析，也必须返回标准 Roll。

## Roll 的值契约

```text
一次 := 4d6kh3
一次.total     # Int 或 Float，总值
一次.faces     # List<Int>，按抽样顺序展平的原始骰面（含舍弃的骰子）
一次.dice      # List<Object>，每枚骰的 raw/effective/kept/round 等元数据
一次.trace     # 结构化表达式/骰点计算树
一次.detail    # 用户可读的计算过程文本
```

`faces` 是**原始面值**，不反映 `min/max` 截断；有效值请查 `dice[i].effective`。`dice[i].kept` 对保留/舍弃有明确布尔标识；多轮骰点增加 `.round`（从 1 开始）。`trace` 对每个抽样节点保留独立的抽样身份，便于判定“同一结果被引用两次”和“独立抽了两次”。

- `Roll + Int/Float/Roll`、`Roll - ...`、`Roll * ...`、`Roll / ...`、`Roll ** ...` 均得到带计算轨迹的 Roll（若运算合法）。
- `Roll` 与数值比较按 `.total`，比较返回 Bool。两个 Roll 比较其数值，不自动比较 trace。
- `Int(roll)` / `Float(roll)` 返回纯数值，不再保留计算轨迹。
- `roll + "伤害"` 无效；需要拼文本用反引号模板：`` `伤害：{roll}` ``。
- Roll 的默认 `to_text()` 展示的是最终值；若希望显示完整过程，显式使用 `.detail`。宿主可决定在扩展信息中同时展示 trace，但不得改变 `.total`。

示例：

```text
r := d6
r + r                       # 同一次样本值加两遍，trace 可见两次引用
[d6, d6].sum()              # 两次独立样本，trace 含两个抽样节点
```

对于跨多轮/特殊骰池，`Roll.total` 不一定是单纯的骰面和：WoD 表示成功数、DX 按轮数规则结算。不要在宿主层自行重新统计所有 `.faces` 来推断 `.total`。

## Formula（取代 computed 的能力，不复制隐式语义）

```text
攻击 := formula(ctx => d20 + ctx.加值)
人物 := { 加值: 4, 命中: 攻击 }

人物.命中                       # Formula 本身（不求值）
人物.命中.eval(人物)           # 新一次随机计算
人物.命中.eval(人物)           # 再算一次
```

`formula(f)` 的实参必须是可序列化的语言函数，且其可调用体满足**公式效果限制**：允许读取 `ctx`、读取已捕获的不变常量、调用纯函数、随机抽样；禁止赋值/对象变更、宿主持久化写入、I/O、调用不声明为纯的宿主函数。检查器尽力静态检查，运行时必须再次执行业务效果校验。

- `f.eval(ctx)` 的结果是公式返回的原始值：可为 Int/Float/Bool/String/Roll/Object，若没有值则 Unit。
- `f.bind(obj)` 得到新的 Formula（不修改原公式），绑定字段成为默认 `ctx` 值；`.eval(explicit)` 中明确提供的字段覆盖绑定默认值。
- `f.eval()` 只有在所有必需的 `ctx` 字段都已绑定时合法，否则给出“缺少上下文属性”的错误。
- 公式中的随机抽样每次 `.eval()` 独立发生；仅从对象读取公式并不会产生骰点。
- 公式可以捕获可序列化的不可变常量；若闭包捕获可变对象，对其做只读快照并封入公式，不能持有指向可变宿主状态的隐式引用。

**与 DiceScript 的关键差异**：旧 computed 的读取即执行、带 `this` 的附加空间和 `loadRaw*` 不原样移植；通过 `Formula` 字段 + 显式 `.eval(ctx)` + `.bind()` 覆盖对应能力。

## 随机源、资源限制

骰子抽样由宿主注入同一可复现随机源；内部集合 `.rand/.randSize/.shuffle` 同样消耗该源。每次求值记录抽样次数和轨迹，受如下预算共同约束：骰子枚数、骰面范围、爆骰轮次、程序操作次数、递归深度、分配、字符串长度、序列化大小。预算耗尽必须报错，不能无声截断结果。`Roll` 和 `Formula` 均按保留抽样身份/代码的结构化数据序列化，不能只序列化 `.detail` 字符串。
