## 解析阶段

严格解析器按以下顺序执行：

1. 检查输入 Unicode 标量值；以字节接收时使用严格 UTF-8 解码。
2. 扫描正文转义和标签候选，使用固定结构空白字符表。
3. 扫描引号及通用 `/]` 结束符，读取属性和位置参数。
4. 匹配容器标签；`[code raw]` 使用[专用原样读取规则](../code/)。
5. 形成 Text / Element 树，展开 `[@...]` 与 `ref` 等简写。
6. 应用[消息树正规化](../model/)和语义校验。

严格模式遇到错误必须停止，并报告诊断代码及错误位置。错误位置采用从 0 开始的 Unicode 码点偏移，可附加行号和列号。

## 诊断代码

| 代码 | 类别 | 示例 |
| --- | --- | --- |
| `E_TAG` | 标签未闭合或不可读取 | `[:x` |
| `E_NAME` | 元素或属性名称不合法 | `[:1x/]` |
| `E_ATTR` | 属性格式或字符串非法 | `[:x a=]` |
| `E_ATTR_DUP` | 重复属性 | `[:x a=1 a=2/]` |
| `E_CLOSE` | 结束标记不匹配 | `[b]x[/i]` |
| `E_SCHEMA` | 内置元素违反结构规则 | `[img]` |
| `E_PARENT` | 元素放置位置不合法 | 根级 `[ref 42]` |
| `E_SHORT_CLOSE` | 没有属性值的容器简写尝试自闭合 | `[b/]` |
| `E_RAW_CLOSE` | 原样代码缺少关闭标记 | `[code raw]...` |
| `E_UNICODE` | Unicode 字符序列非法 | 未配对的代理码位 |
| `E_LIMIT` | 超过实现资源限制 | 超过最大嵌套深度 |

消息树构造 API 应提供相同的语义检查及可定位的节点路径。错误恢复与宽容模式可以作为额外功能；宽容模式输出需标示为恢复结果。

## 错误示例

| 输入 | 处理结果 |
| --- | --- |
| `[note]` | 普通文本 |
| `\[@123]` | 普通文本 `[@123]` |
| `[@123]` | `at` 元素 |
| `[img]` | `E_SCHEMA`，缺少 `src` |
| `[img foo=bar]` | `E_SCHEMA`，`foo` 被读作命名属性，缺少 `src` |
| `[:x]` | `E_CLOSE`，缺少 `[/x]` |
| `[b]内容[/i]` | `E_CLOSE`，结束标签不匹配 |
| `[/x]` | `E_CLOSE`，多余的结束标签 |
| `[:x a=1 a=2/]` | `E_ATTR_DUP` |
| `[forward]hello[/forward]` | `E_SCHEMA`，`forward` 直接包含非空白文本 |
| `[ref 42]`（根级） | `E_PARENT` |
| `[code raw]未关闭` | `E_RAW_CLOSE` |

## 资源预算

参考实现默认采用：输入最多 1,000,000 个 Unicode 码点、64 层容器、10,000 个节点；外部消息树校验同样限制深度和节点数。实现可以另设属性长度与内存预算。

## 实现约束

- 解析只创建数据结构。解析器不得执行脚本、插件动作或外部资源访问。
- 解析器不得执行 Unicode 归一化，不得修改正文中的换行、缩进或组合字符。
- 未知通用元素必须能够在消息树与规范化文本之间往返。
- 严格解析器必须标明所实现的 CQX 版本。
- 实现应限制最大输入长度、最大嵌套深度、最大节点数及属性大小，防止恶意深度嵌套和超大消息消耗资源。
