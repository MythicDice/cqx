## 正文字符

正文中的 `&`、`<`、`>`、`,`、`=`、`]` 直接保留。没有被识别为标签的方括号文本也原样保留：

```text
这是普通文字：[note]、[1,2,3]、a&b、<x>。
```

标签候选的识别顺序请参考[标签、名称与属性](../format/)。已识别的候选若格式或结构错误，严格解析器必须报告错误，不能退回为正文。

## 转义

正文只定义两种反斜杠转义：

| 输入 | 解析结果 |
| --- | --- |
| `\[` | 字面字符 `[` |
| `\\` | 字面字符 `\` |

其他正文反斜杠序列保留原样：

```text
真正的提及：[@123]
字面的提及：\[@123]
Windows 路径：C:\Users\Alice
```

规范化序列化器必须对所有正文中的 `\` 和 `[` 执行相应转义，从而确保任意合法纯文本在重解析时继续是纯文本。

> **注意**
>
> 通用标记入口 `[:` 与结束标签 `[/name]` 是保留形式。要字面显示这些标记，必须转义左方括号，例如 `\[:img src="a.png"/]`。

## 空白规则

1. 一般正文必须保留全部 Unicode 字符、缩进和换行，包含 CRLF 与组合字符；解析器不执行 Unicode 归一化。
2. `forward` 容器直接包含的纯结构空白节点被删除；其中结构空白为 U+0009、U+000A、U+000D、U+0020。
3. `msg` 内的正文保留所有字符；不自动修剪首尾空白、不处理缩进、不统一换行。
4. 扩展容器内的所有正文空白保留。

```text
[forward]
  [msg user=1]
    第一行
    第二行
  [/msg]
[/forward]
```

上例 `msg` 的正文包含开头与结尾的真实换行，以及每行的四个空格；`forward` 直接子节点之间的换行与缩进则不属于消息树。

`forward` 直接出现非空白正文或其他元素时必须报错，详见[合并转发与消息引用](../forward/)。
