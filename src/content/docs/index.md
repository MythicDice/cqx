本草案规定 CQX v0.3 的消息文本格式。

## 范围

CQX 规定消息的文本表示、简写与通用写法的对应关系、原样围栏、解析所得的抽象消息树，以及由消息树生成文本的规范化序列化。

文中的 **必须** 表示实现符合本草案的必要条件，**应该** 表示推荐行为，**可以** 表示可选行为。

v0.3 的简写名称、标签识别、原样围栏和转义规则在本版本内固定。解析器必须标明所实现的 CQX 版本；支持多版本的解析器必须显式指定版本，或通过协议封装确定版本。

> **注意**
>
> CQX 文档是一段 Unicode 文本，以字节传输时应使用 UTF-8 编码。解析器不得执行 Unicode 归一化。

## 字符串格式

在 CQX 中，无论纯文本还是提及、图片、表情等特殊内容都写在同一个字符串里，即，一条消息对应一个字符串。以下是一个 CQX 消息的例子：

```text
你好，[@123456]！
[reply 98765]看看照片：[img cat.png]
收到啦。[face 14]
```

消息中的特殊内容使用「消息元素」表示，形如 `[img cat.png]`。其中，`img` 是「元素名」，`cat.png` 是「位置参数」。元素之间可直接连接，无需分隔符；正文中的换行予以保留。

一些消息元素的例子如下：

```text
[@123456]
[@all]
[face 14]
[:acme.poll title="今天吃什么？"/]
```

更多消息元素请参考[内置消息元素](segments/)。

## 两种写法

「简写」用于日常输入，「通用写法」用于扩展、数据交换和规范化输出。

| 简写 | 通用写法 |
| --- | --- |
| `[@123]` | `[:at id="123"/]` |
| `[@all]` | `[:at type="all"/]` |
| `[img cat.png]` | `[:img src="cat.png"/]` |
| `[reply 42]` | `[:reply id="42"/]` |

简写在语法分析阶段展开为通用消息树。同一消息树可以有多种可手写的输入形式，但只对应一种规范化文本形式。例如，下面两行解析成相同消息树：

```text
[img cat.png]
[:img src="cat.png"/]
```

更多格式规则请参考[标签、名称与属性](format/)。

## 原样内容

围栏之间的字符不参与标签识别：

```text
[code]print("[@all]")[/code]
[raw]这里的 [@all] 是普通文字[/raw]
```

`code` 生成代码容器，`raw` 只生成正文。详见[原样围栏](code/)。
